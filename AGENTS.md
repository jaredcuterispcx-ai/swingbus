# swingbus — project context

Handoff notes for anyone (human or AI agent) picking this project up. Read this before making changes.

## What it is

A shuttle app for the XSI / MEM campus (Macroharder + offsite lots, Memphis/Southaven). It replaces a human dispatcher on the phone: riders say where they are and where they're going, drivers share GPS and log pickups, and the server routes the nearest shuttle with free seats.

Name is always lowercase, even at the start of a sentence: **swingbus** (never "Swingbus" or "Swing Bus"). Footer on every page: "swingbus brought to you by your friends in Transportation and Observability Software." plus "Feedback? Find us at #memphis-transportation on Slack."

## Core user flows (the product owner's words, keep these intact)

**Passengers**
1. Scan the QR code at a stop, or pick the pickup stop on the home page.
2. Choose a destination.
3. Choose passenger count, request.
4. While waiting: see **all shuttles** and **which one is coming to their stop next**.

**Drivers**
1. Start a session with a shuttle name — autogenerated "electric" callsign (e.g. Volt, Phase, Vector), editable. Names are unique among online shuttles; a number is appended only if the name is already taken.
2. The phone's location services track the shuttle.
3. Driver sets where they're heading.
4. Driver logs who they picked up at each stop: one or more groups, each = passenger count + destination.
5. Location-aware: within a stop's arrival radius (75 m default, per-stop override) the phone is "at" that stop; pickup stop auto-fills, stop lists sort nearest-first.

**Admin** (`/admin`): rename, move, add, delete stops; persisted. "Use my location" while standing at a curb, or paste `lat, lng`. Optional `ADMIN_PIN` env var gates edits.

## Design direction

- Mimic the Uber app: white background, black text and primary buttons, gray (#EEE) inputs, list rows with hairline dividers, big single call-to-action.
- One accent color: electric yellow `--volt` (#FFD400). Use it as a fill (logo bolt, live dot, "at stop" chip), never as text on white.
- Logo: yellow lightning bolt on a black rounded square (`public/bolt.svg`, `src/components/brand.tsx`).
- Minimize text. No explanatory paragraphs on selection screens.
- Mobile first: inputs are 16px (prevents iOS zoom), tap targets ≥ 44px, destination picking is a tappable list rather than a dropdown.
- The map is a schematic SVG (`src/components/mini-map.tsx`) — no tile provider, works offline. It frames the main campus cluster and clamps far-off lots (Southland Mall) to the edge.

## Architecture

- Next.js 15 App Router + TypeScript + Tailwind v4. No database: state lives in `data/store.json` (gitignored), written through a serialized write chain in `src/lib/store.ts`.
- Clients poll `GET /api/state` (2–8 s depending on page).
- Fonts are bundled via `@fontsource-variable/*`. Do **not** switch back to `next/font/google`: it downloads at boot and failing downloads took the whole app down.
- Custom CSS classes (`sb-*`) live in `@layer components`, base resets in `@layer base`, so Tailwind utilities can override them. Unlayered rules beat utilities — that bug once hid button labels.

Key modules (`src/lib/`):

| File | Role |
|------|------|
| `types.ts` | Stop, PassengerParty, Vehicle, Clearance, BoardingEvent, AppState |
| `store.ts` | Persistence, migrations (`SCHEMA_VERSION`), all mutations incl. stop CRUD |
| `dispatch.ts` | Ground-control routing: issues clearances (seat holds) to the nearest vehicle with room |
| `seats.ts` | Seat ledger: `available = capacity − occupied − reserved` |
| `fleet.ts` | Per-stop ranking of shuttles + ETA (haversine, ~22 km/h) for the waiting view |
| `geo.ts` | Distances, arrival radius, nearest stop |
| `callsigns.ts` | Electric callsign generation + uniqueness |
| `stops.ts` | Default MEM stop list (seed only; admin edits are the source of truth after that) |

API routes (`src/app/api/`): `state` (GET, DELETE = reset riders/fleet but keep stops), `parties`, `vehicles` (register / location / heading / active / accept_clearance), `board` (board + alight), `stops` (CRUD + `restore_defaults`), `dispatch`, `demo/seed`. Legacy aliases: `requests`, `drivers`, `pickups`.

Pages: `/` home, `/passenger/[stopId]`, `/driver`, `/dispatch` (ground control), `/admin`, `/stops` (printable QR codes), `/deploy` (phone-access notes).

Nine stops from the "MEM Shuttle Info" sheet: Food Trucks / War Room, Crossroads, Macroharder West, Macroharder East, Church Parking Lot (Surge Concierge / Onboarding), Southland Mall Parking Lot, Duke, Gun Range, Spam / Nexus. Each is tagged onsite / offsite / both.

Service hours from the sheet: onsite shuttle 24/7; offsite 5–10 AM and 5–10 PM. Dispatcher phone: (956) 658-1860.

**Coordinates are approximate placeholders** (geocoding was blocked in the build environment). ETAs and "next shuttle" ranking are only rough until real pins are entered in `/admin`.

## Running

```bash
npm install
npm run dev                  # http://127.0.0.1:43127
./scripts/dev-forever.sh     # same, auto-restarts if the server exits
```

Phones off the corporate network: run on a stable internal host and expose it with Tailscale Funnel (`scripts/expose-funnel.sh`, `DEPLOY.md`). Ephemeral sandboxes and free quick-tunnels were unreliable.
